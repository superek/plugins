# loop:browser — 코드가 아니라 화면을 본다

## Quality Gate (이 4개를 못 지키면 "화면 확인함"이라고 쓰지 않는다)

1. **실제로 띄워서 본 것만 화면 사실이다.** 코드를 읽고 추론한 것은 코드 사실이다 (`loop:review` Phase 3①).
2. **기본 상태만 보고 끝내지 않는다.** 결함은 기본 상태에 거의 없다 (Step 3).
3. **본 것을 증거로 남긴다.** 스크린샷·콘솔·네트워크 중 최소 하나.
4. **쓰기 조작 전에 대상 환경을 확인한다.** 내가 만든 데이터가 남의 화면에 남을 수 있다.

---

## Step 0 — 이 환경의 도구부터 확인한다 (이름을 가정하지 않는다)

브라우저 제어 수단도, 앱 실행 방법도 프로젝트마다 다르다. **없는 도구를 가정하면 조용히 아무것도 못 한다.**

| 찾는 것 | 어디서 | 예시 (환경마다 다름) |
|---|---|---|
| **브라우저 제어** | 사용 가능한 도구 목록 | 브라우저 자동화 MCP, CDP 기반 도구, Playwright/Puppeteer |
| **앱 실행 방법** | `package.json` scripts, README, 프로젝트 실행 스킬 | `dev`·`start`·`preview` |
| **접속 주소** | 실행 로그에 찍히는 것 | 포트를 추측하지 말고 **로그에서 읽는다** |

도구가 하나도 없으면 **거기서 멈추고 그렇게 말한다.** "확인한 셈 치고" 넘어가지 않는다 — 그러면 코드 사실을 화면 사실로 승격시키는 것과 같다.

## Step 1 — 무엇을 볼지 **먼저** 쓴다

```
어디: <화면 / 경로>
조작: <무엇을 누르나>
기대: <무엇이 보여야 하나>
```

이걸 안 쓰고 띄우면 **보이는 것을 기대였다고 착각한다.** 결과를 본 뒤에 기준을 만들면 검수가 아니라 감상이다.

## Step 2 — 띄우고 기본 상태를 본다

- 화면이 **뜨는 것**과 **맞게 뜨는 것**은 다르다. 뜬 걸로 만족하지 않는다.
- 여기서 이상하면 Step 3으로 가기 전에 먼저 정리한다.

## Step 3 — 결함이 숨는 4개 축을 **만들어서** 본다 (이 스킬의 핵심)

**기본 상태는 개발 중에 이미 수백 번 봤다. 결함은 거기 없다.** 모국어·실데이터·넓은 화면에서는 안 보이는 것들:

| 축 | 만드는 법 | 잡히는 결함 |
|---|---|---|
| **로케일** | 모국어 말고 **라벨이 긴 언어**로 전환 | 고정폭 깨짐, 줄바꿈, 말줄임, 잘림 |
| **데이터 경계** | `0` · `null` · 음수 · 100% 초과 · 아주 긴 문자열 | 포맷 오류, 나눗셈, 빈 상태 누락 |
| **화면 폭** | 좁은 뷰포트로 리사이즈 | 겹침, 가로 스크롤, 버튼 밀림 |
| **상태** | 로딩 중 · 에러 응답 · 빈 목록 · 권한 없음 | 무한 스피너, 처리 안 된 실패 |

> 실제 사례: 타입체크·린트·테스트가 **전부 통과**인데 결함 5건이 나왔다. 원인은 **모국어 로케일 + 실데이터만 본 것**이었다. 다국어 라벨은 고정폭에서 깨졌고, 0·null·100% 초과 같은 값은 실데이터에 애초에 없었다.

**실데이터에 없는 값은 만들어서 본다.** 응답을 가로채 바꾸거나, 목(mock)을 넣거나, 그런 값을 가진 계정·레코드를 쓴다. "그런 데이터가 없어서 못 봤다"는 확인하지 않은 것이다.

## Step 4 — 콘솔과 네트워크를 같이 본다

화면이 멀쩡해 보여도 **콘솔에 에러가 쌓이고 있을 수 있다.** 그리고 값이 틀렸을 때 원인이 표시인지 데이터인지는 응답을 봐야 갈린다 (`loop:trace` Step 2 층 가르기).

- 콘솔: 에러·경고. 양이 많으면 **패턴으로 걸러서** 본다
- 네트워크: 그 화면이 실제로 부른 요청과 **응답 본문**. 기대한 값이 실제로 왔나

## Step 5 — 증거로 정리하고 넘긴다

```
[확인] <어디> — <조작> → <실제로 보인 것>
  증거: 스크린샷 / 콘솔 N건 / 응답 <필드>=<값>
  판정: 기대와 같음 / 다름(<어떻게>)
```

- 다른 게 있으면 → **`loop:review`** 렌즈 2·3으로 넘긴다 (화면 사실 딱지를 붙여서)
- 원인을 모르겠으면 → **`loop:trace`**

## 조작 전 주의

- **확인 대화상자를 띄우는 조작**(삭제 버튼 등)은 자동화 세션을 멈춰 세울 수 있다. 누르기 전에 알린다.
- **쓰기(생성·수정·삭제)는 대상 환경을 먼저 확인한다.** 로컬에서 띄운 서버가 로컬 DB가 아니라 **공유 개발 DB**를 보고 있는 경우가 있다 — 내가 만든 테스트 데이터가 남의 화면에 남는다.
- 쓰기가 꼭 필요하면 **임시 계정·임시 값으로 하고 끝나면 되돌린다.**

## 비용 통제

화면 하나에 4개 축을 전부 돌리면 비싸다. **변경이 닿은 축만** 고른다.

| 변경 성격 | 반드시 볼 축 |
|---|---|
| 라벨·문구·번역 | 로케일 · 화면 폭 |
| 숫자·계산·포맷 | 데이터 경계 |
| 목록·조회 | 상태(빈 목록·에러) · 데이터 경계 |
| 레이아웃·컴포넌트 | 화면 폭 · 로케일 |

## 금지

- ❌ 안 띄우고 "화면 확인함" 쓰기 (= 코드 사실을 화면 사실로 승격)
- ❌ 기본 상태만 보고 통과 처리
- ❌ "그런 데이터가 없어서 못 봤다" 로 끝내기 — 만들어서 본다
- ❌ 포트·주소를 추측해서 접속 시도 (실행 로그에서 읽는다)
- ❌ 도구 이름을 가정하고 시작하기 (Step 0)
- ❌ 스크린샷 없이 "정상으로 보임" 보고
- ❌ 확인 대화상자가 뜨는 조작을 예고 없이 누르기
- ❌ 대상 DB 확인 없이 쓰기 조작
